研究 pipeline

Pipeline 将来源事实和交易轨迹适配分开。模型负责提出结构化记录，确定性检查负责拒绝没有原文支持、缺少字段或无法映射到框架的记录。

01 · CORPUS

材料与 provenance

保存 URL、日期、版本、作者边界、hash 和完整文本。书籍只在研究者合法取得后本地处理。

02 · STAGE 1

Principle extraction

从完整文本提取作者明确陈述或强重复的原则，保留连续原文引文、条件、例外和出处。

03 · STAGE 2

Rubric compilation

将原则编译为可以在 trading agent trajectory 中观察的 criterion、适用条件、证据和判定规则。

04 · EVALUATION

Trajectory audit

在 TradeBank 或其他框架中评测 pass、violate、not_applicable、not_observable，并报告 coverage。

研究目标

衡量 Trading Agent 的行为有多符合某位大师的投资风格，并定位错误首先出现于证据读取、分析、估值、仓位还是执行环节。

与 financial outcome 的关系

收益、回测和波动可以作为结果层指标，但不能单独证明风格忠实。Rubric 评估先审计过程，再与金融结果和专家判断对照。

为什么不同大师不一定需要书？
Buffett 的股东信、Marks 的官方 memo、Ackman 的投资者信、Soros 的官方文章本身就是连续、可追溯的一手表达。Munger 的书是编选/编辑材料，Greenblatt、O’Neil、Dalio 的核心书籍则会显著补充公开 corpus。因而书籍是 source tier 的补充，不应被默默删除，也不必机械地成为每位大师唯一的来源。

Rubric 如何连接 Trading Agent

Rubric core

描述大师原则本身：criterion、适用条件、原文及出处、operationalization、evidence requirements、pass/violation/unknown 规则。

Canonical trajectory

统一记录 observation、market_context、agent_reasoning、action、order_parameters、outcome 和 source_refs。

Framework adapter

TradeBank 只负责把自己的 action、reasoning、timestamp 和 outcome 字段映射到 canonical trajectory；Rubric core 不随单条 episode 改写。

四种评测状态

  • pass：有足够证据支持符合。
  • violate：有足够证据支持违反。
  • not_applicable：触发条件没有出现。
  • not_observable：条件适用，但轨迹缺少必要 context。

覆盖率报告

coverage = (pass + violate)
          / (pass + violate + not_observable)

observable_score = pass / (pass + violate)
关键防误判：TradeBank 没有提供估值、组合或市场 context 时，不能把“没有展示安全边际”直接判为违反 Buffett 原则，应返回 not_observable。

自动验证和当前局限

已经执行的检查

  • JSON 结构和必需字段。
  • supporting quote 是否能在完整来源文本中找到。
  • rubric 是否引用了框架中存在的字段。
  • 稳定 ID、重复记录和 source provenance。
  • criterion 的原子性提示。

仍需要人工处理

  • “criterion may contain more than one behavior” 警告需要逐条审查。
  • 相近 principle 的跨文档去重。
  • 区分作者明确原则、重复表达和强推断。
  • 由金融专家判断风格特异性、适用条件和反例。
  • 确认不同大师之间的来源覆盖度可比。
Munger 的 4 条 rejected 记录
1997.txt 拒绝 2 条，1998.txt 拒绝 1 条，2001.txt 拒绝 1 条。它们的共同原因是模型给出的引文无法在抽取后的完整文本中定位为连续片段。源文件仍保留，合法的可验证原则继续进入 stage2；拒绝记录位于本地运行目录下各文档的 principles.rejected.jsonl。
为什么严格总数仍然是 434？
434 是冻结的 strict public canonical subset。Greenblatt 和 O’Neil 的新增材料有 supporting/institutional 作者边界，Dalio 的新增报告是 expansion，Munger 的补跑包含旧结果。因此扩展输出单独报告，避免把不同 source tier 混成一个统计口径。

复现入口

本地材料抓取脚本：

python buffett_corpus/fetch_materials_20261010.py \
  --out buffett_corpus/materials_local

单个完整文本运行两阶段 pipeline：

python -m buffett_corpus.pipeline.cli \
  --documents <complete-document.txt> \
  --master "<master>" \
  --framework buffett_corpus/configs/tradebank.json \
  --out buffett_corpus/runs/<run-name>

API key 只从环境变量读取。原始 PDF、完整版权文本和 generated runs 默认被 gitignore；运行状态和材料 registry 会提交到仓库。
